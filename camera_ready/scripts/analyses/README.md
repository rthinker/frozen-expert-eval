## Three-class protocol

Steps C14 to C20 produce the exploratory three-class comparisons of Appendix I.1. This section records the settings
of the current scripts. The release claims no preregistration: the stored key `registered_n_perm` is a retained name
for the default permutation count, and `paper_labels_follow_registry` records that the method labels follow this
section.

### Rows and folds

| | Construction A (`A_df40`) | Construction B (`B_arch6`) |
|---|---|---|
| Experts | `df40-clip-large`, `df40-clip-base`, `df40-xception` | `fs-clip-base`, `fs-clip-large`, `fs-xception`, `fs-srm`, `fs-recce`, `fs-rfm` |
| Classes | entire-face synthesis, face swap, reenactment | GAN synthesis (StyleGAN2, StyleGAN3, StyleGANXL, VQGAN), diffusion synthesis (DiT, SiT, ddim, pixart, rddm, sd2.1), reenactment; face swap excluded |
| Stored manifest | 20,633 rows, 5 folds | 14,121 rows, 3 folds |

Both constructions use fake FIT and SELECT rows whose path appears in exactly one of DF40's `FSAll_ff`, `FRAll_ff`
and `EFSAll_ff` fake lists, as rewritten by C00. Rows whose content hash matches any row of the eight held-out
generators are removed. Families (the first path component) that share content form one group.

The fold assignment uses no randomness. Within each class, groups are taken by descending row count (ties by name),
and each goes to the fold holding the fewest rows of that class (ties to the lowest fold index). The number of folds
is the number of groups in the rarest class, capped at five. Every fold needs at least 150 test and 400 training
rows per class, and no content may cross folds.

In outer fold `f`, TRAIN is the FIT rows of the other folds, SELECT is the SELECT rows of the other folds, and TEST
is every row of fold `f`.

C14 builds construction A's folds in `K3_folds_df40.json`. C15 checks each row's path against each expert's training
list: construction A is expected to be 100% exposed in every class and construction B 0%. C16 writes
`K3_FROZEN_<view>.json` for both constructions. Its `manifest_sha256` covers the `split|idx|fold|class` lines sorted
by split and row index, and the fitting scripts refuse a manifest that no longer matches it.

### Fixed binary outputs (C17, C18)

`appI1_k3_fit.py` uses the experts' original binary outputs.

* **Logistic recipe:** `StandardScaler` fitted on TRAIN, then `LogisticRegression(max_iter=3000, C=1.0,
  class_weight="balanced")` with scikit-learn's default L-BFGS solver and tolerance (1e-4). The iteration count is
  not recorded.
* **`FS-LR(std)-K3`:** the logistic recipe on concatenated features. It is not the paper's FS1.
* **`PS-bin-to-K3 adapted ceiling`:** SELECT macro one-vs-rest AUROC chooses one map and one head. The maps are
  logits, disagreement, uncertainty with mutual information, quadratic and rank. The heads are the logistic recipe or
  XGBoost with `objective="multi:softprob"`, 50, 100 or 200 trees, depth 2, 3 or 4, learning rate 0.1, subsample 0.8
  and column subsample 0.8. It is not the complete PS1 to PS4 ladder.
* **Temperatures:** the uncertainty map fits them on binary SELECT, real rows included, without held-out-generator
  content and without the content of the test fold.
* **Primary contrast:** the mean over folds of `FS-LR(std)-K3` minus the SELECT-chosen ceiling, in TEST macro
  one-vs-rest AUROC. It is descriptive only. A different rung that scores higher on TEST is reported as a note and is
  not adopted.
* **Secondary results:** PCA fitted on TRAIN to twice the number of experts, then the logistic recipe; and pooled
  out-of-fold macro one-vs-rest AUROC.
* **Control:** class labels shuffled across TRAIN groups, 20 permutations by default (`--n-perm`). Each permutation
  fits the logistic recipe to both the features and the logits. Chance is 0.5.

### Task-specific heads (C19, C20)

C19 (`appI1_native_k_preflight.py`) fits no model. It freezes the inner assignments with `StratifiedGroupKFold`: the
largest valid number of splits from 5 down to 2, shuffled, with `random_state` 1024 plus the outer fold, recorded in
`assignment_sha256`.

`appI1_native_k_heads.py` fits one three-class head per expert on the frozen binary-trained backbones: `StandardScaler`,
then `LogisticRegression(C=1.0, class_weight="balanced", max_iter=500, solver="lbfgs", tol=1e-3, random_state=1024)`.
This tolerance is ten times looser than scikit-learn's default and is recorded as `head_tolerance`. Cross-fitted
heads give the TRAIN logits, and a final head refit on all outer TRAIN rows gives the SELECT and TEST logits.

`appI1_native_k_aligned_v2.py` then evaluates these combiners:

| Method | Setting |
|---|---|
| PS1-K3 | Mean three-class probabilities |
| PS2-K3 | Unscaled multinomial logistic regression on logits (L-BFGS, `C=1`, class-balanced, `max_iter=1000`, `random_state=1024`), recording `n_iter` and `convergence_warnings` |
| PS3-K3 | MLP with 64 hidden units, dropout 0.1, 10 epochs, batch 256, learning rate 2e-4, averaged over seeds 7, 10, 24, 42, 1024, 1973, 3392 and 9721 |
| PS4-K3 | XGBoost with 5-fold CV inside TRAIN over 108 configurations: `n_estimators` 50/100/200, `max_depth` 2/3/4, `learning_rate` 0.05/0.1/0.3, `subsample` 0.8/1, `colsample_bytree` 0.8/1 |
| FS1-K3 | Unscaled multinomial logistic regression on raw concatenated features, same recipe with `max_iter=2000` |
| FS2-K3 | Projection MLP with `d=256`, hidden layers 512 and 256, dropout 0.1, expert dropout 0.25, 10 epochs, the same eight seeds |
| FSB-K3-18 | PCA fitted on TRAIN to 18 components (experts times classes), then the FS1-K3 recipe |
| PS+-K3 | Separately labelled diagnostic ladder chosen on SELECT |

Core PS is the method SELECT chooses among PS1-K3 to PS4-K3. The recorded contrasts are
`FS1_minus_select_chosen_core_PS`, `FS2_minus_select_chosen_core_PS`, `FS1_minus_PS_plus` and `FS2_minus_PS_plus`.
`core_ps_test_max_diagnostic` is a TEST maximum marked `non_deployable`, not a selected comparator.

`appI1_native_k_heads.py` also runs by hand as a targeted diagnostic with `FS-LR(std)-K3`, `FSB(std)-K3` and the
`PS+-K3 diagnostic ceiling`. These are not the paper's FS1, FS2 or complete ladder. The `--smoke` mode of both scripts
uses only outer-FIT rows and marks its output `SMOKE_INTERNAL_FIT_ONLY_DO_NOT_REPORT`.

## Width-control directions

The label-fitted directions of the width controls (`appD_width_controls.py` and
`../runs/05_run_c_width_matched_v5.py`) use `LogisticRegression(C=1.0, max_iter=2000, solver="lbfgs")` without class
weights, unlike the class-balanced FS1. The standard split's FIT holds 5,438 real and 21,153 fake rows.
