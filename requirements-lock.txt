# Direct-dependency pin file from a successful reproduction run on
# Windows / Python 3.11. This is NOT a fully hermetic lockfile: only the
# direct project dependencies are pinned here, and pip resolves transitive
# dependencies at install time, so minor environment drift is possible on
# different platforms / pip versions. For reproduction within a small
# numerical tolerance, install into a clean virtual environment:
#
#     python -m venv .venv
#     .venv\Scripts\activate          (Windows)
#     source .venv/bin/activate       (Linux / macOS)
#     pip install -r requirements-lock.txt
#
# The pinned versions below are exactly the ones used to produce the
# numbers in output/results/*.json and output/results/reference_results.json.
# Reviewers who need byte-identical reproduction should regenerate a
# fully-pinned environment by running `pip freeze > requirements-full.txt`
# inside a clean venv after installing from this file.
#
# CUDA NOTE: torch is pinned to a CUDA 12.8 build (cu128) via the
# --extra-index-url directive immediately below. Without that line,
# `pip install -r requirements-lock.txt` would resolve `torch==2.10.0`
# from the default PyPI index and silently install the CPU-only build,
# breaking the GPU-runtime claim in the paper. Reviewers without a
# matching CUDA toolchain can override to a CPU build via
#     pip install torch==2.10.0+cpu torchvision==0.25.0+cpu \
#       --index-url https://download.pytorch.org/whl/cpu
# All scripts are CPU-feasible after the feature cache is populated.
